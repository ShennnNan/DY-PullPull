# DY-PullPull 当前计划（轻量可实现路径）

> 本文是项目当前主线计划，2026-06-16 起取代原 v0.1–v0.4 重设计。
> 原设计降为备选，见 `docs/superpowers/` 下的 specs / plans。
> 原则：先做出一套能用的，快速输出结果，质量靠迭代和 AI 后处理补足。

## 最终目标

1. **公开收藏归档**：直接读取用户的公开收藏，把全部收藏内容的文本整理到本地。
2. **账户作品归档**：读取指定账户的全部原创视频，把每条的文本原文与总结整理到本地。

两个目标复用同一条单条管线，差异只在"如何枚举出待处理的链接"。

## 主线架构

```text
输入（单链接 / 账户主页 / 公开收藏页）
  -> 枚举视频 URL 列表              [枚举器]
  -> 逐条:
       yt-dlp 下载                 [下载]
       FunASR paraformer-zh 转写   [转写]
       AI 整理（原文清洗 + 总结）   [后处理]
  -> 保存本地 Markdown + index.json [存储]
```

三块积木：

- **A. 单条闭环**：链接 → 下载 → 转写 → AI 整理 → 本地文件。已端到端验证（AI 整理待自动化）。
- **B. 枚举器**：把账户主页 / 收藏页展开成链接列表，逐条喂给 A。
- **C. AI 后处理**：转写原文 → 纠正同音字 / 英文术语 / 补漏 + 生成总结。

## 技术取舍

- **下载 / 枚举**：统一 `yt-dlp`（内置抖音解析，支持单条、账户作品列表；需登录内容用 `--cookies-from-browser` 复用用户本人登录态，不绕风控）。今天试过的 majin72 parse 脚本留作单链接备用。
- **转写**：主引擎 FunASR `paraformer-zh`（CPU 也快、中文专精、自带 VAD + 标点）；faster-whisper 作备选 / 回退（GPU 高质量、中英混读更强）。
- **后处理**：AI 在整理阶段纠错与总结，不要求 ASR 一次到位。
- **存储**：每条一份 `.md`（原文 + 总结 + 来源元数据）+ `index.json` 去重和断点续跑；暂不上 SQLite。
- **临时媒体**：下载的视频 / 音频成功转写后删除，本地只长期保留文本。

## 产物格式（每条一份 Markdown）

```markdown
---

（AI 生成）

（FunASR 转写 + AI 清洗）
```

## 阶段拆分

| 阶段 | 目标 | 验收 |
|---|---|---|
| **P1 单条闭环** | 把"yt-dlp 下载 → FunASR 转写 → 写一份 md"串成一个命令 | 给一个链接，得到一份含转写的 md；临时媒体清除 |
| **P2 AI 整理** | 加 C：原文清洗 + 总结 | md 含"原文 + 总结"两段 |
| **P3 账户批量（目标 2）** | yt-dlp 账户枚举 + 批量逐条 + 索引 | 给账户主页，得到 N 份 md，可断点续跑、去重 |
| **P4 公开收藏（目标 1）** | 收藏页枚举 | 给收藏页 / 账户，得到全部收藏文本 |

## 已知风险 / 待验证

- **目标 1 枚举**：抖音收藏默认私密，"公开收藏"能否免登录枚举需先做 spike；不行则复用用户 cookie 读本人收藏。
- **目标 2 枚举**：yt-dlp 抖音用户提取器可用性需实测，部分账户可能需 cookie。
- **反爬 / 风控**：批量需低频，复用本人登录态，不绕验证码。
- **英文术语**：paraformer-zh 对夹杂英文易音译，靠 P2 的 AI 后处理纠正。
