# 抖音收藏文章提炼 Codex Skill 设计

## 1. 项目目标

本项目交付一个面向 Windows 10/11 的 Codex Skill。用户在自己的电脑上登录抖音后，Skill 增量读取用户本人可访问的收藏视频，将视频作为临时分析输入，提取语音、字幕和关键画面文字，再由 Codex 整理成独立 Markdown 文章。

项目首版面向 100 条以内的收藏规模。长期保存的内容只有文章、结构化索引、必要日志和独立浏览器登录态，不保存原视频、音频或关键帧。

项目最初在 GitHub 私有仓库开发。版本稳定后可整理为公开仓库；闲鱼成交后以 ZIP 人工交付 Skill。

## 2. 用户与使用边界

### 2.1 目标用户

- 使用 Windows 10 或 Windows 11。
- 已安装并能使用 Codex。
- 能在独立浏览器窗口中自行扫码登录抖音。
- 优先具有 NVIDIA 显卡；无可用 CUDA 时接受 CPU 回退。
- 希望将个人收藏整理为本地文章，而不是长期保存视频。

### 2.2 合规与隐私边界

- 仅处理用户本人账号能够正常访问的收藏内容。
- 不保存抖音密码，不绕过验证码、访问控制、限流或平台风控。
- 遇到登录失效、验证码或风控时立即暂停，要求用户手动处理。
- 默认串行、低频访问收藏页面，避免对平台产生高频请求。
- 登录态、收藏数据、生成文章、SQLite 数据库、日志和临时媒体均留在用户本机。
- GitHub 和销售 ZIP 不包含任何真实用户数据、Cookie、文章或媒体。
- 商品说明明确该工具用于个人资料整理，用户应自行遵守平台条款、版权和隐私要求。
- 不承诺抖音页面结构或媒体解析方式永久兼容。

## 3. 首版范围

### 3.1 包含

- 独立浏览器配置目录和首次扫码登录。
- 自动滚动收藏页并采集收藏元数据。
- 按视频 ID 增量同步和去重。
- 手工分享链接补录。
- 临时获取分析所需的音频与关键帧。
- 使用 `faster-whisper` 本地转写语音。
- 使用本地 OCR 提取字幕和画面文字。
- 由 Codex 合并材料并生成固定格式的中文 Markdown 文章。
- SQLite 状态索引。
- 每条视频一篇文章和一个合集总目录。
- 失败记录、分步骤重试和断点续跑。
- 处理完成后清理临时媒体。
- Windows、Python、FFmpeg、浏览器、CUDA 和依赖检查。
- `doctor` 诊断流程和中文故障提示。
- 可人工发送的版本 ZIP。

### 3.2 不包含

- 长期保存原视频、音频或关键帧。
- 桌面图形界面或本地 Web 管理界面。
- macOS、Linux 或移动端支持。
- 授权码、授权服务器或在线账户系统。
- 云端转写或第三方总结服务。
- 多用户、服务器部署或分布式任务队列。
- 自动发布、转载或二次上传视频内容。
- 绕过抖音登录、安全验证、下载限制或访问控制。

## 4. 总体架构

Skill 采用“编排层 + 本地工具层 + 本地数据层”的结构。

```text
Codex / SKILL.md
        |
        v
setup / doctor / collector / media / extractor / storage
        |
        v
临时音频与关键帧 -> Whisper + OCR -> 原始材料
        |
        v
Codex 文章提炼 -> Markdown + SQLite -> 清理临时媒体
```

### 4.1 编排层

`SKILL.md` 识别用户意图，并指导 Codex 调用随 Skill 提供的脚本。首版支持以下主要意图：

- 首次安装和环境检查。
- 首次扫码登录。
- 同步新增收藏。
- 补录单条分享链接。
- 分析待处理视频。
- 重试失败项目。
- 重新分析指定项目。
- 生成或刷新合集目录。
- 运行诊断和输出修复建议。

### 4.2 本地工具层

工具层使用 Python CLI，职责边界如下：

- `setup`：检查系统和依赖，创建隔离的 Python 环境。
- `collector`：管理独立浏览器配置，读取收藏页，规范化元数据。
- `media`：在临时目录中准备音频和关键帧。
- `extractor`：运行 Whisper 和 OCR，合并带来源标记的原始文本。
- `storage`：维护 SQLite、文件路径、状态转换和去重。
- `doctor`：检查登录态、浏览器、FFmpeg、Python、CUDA、磁盘和依赖。
- `package`：验证发布内容并生成不含用户数据的 ZIP。

### 4.3 本地数据层

默认数据目录与 Skill 代码目录分离，避免升级或重新安装时覆盖用户数据。数据目录包含：

```text
data/
  library.db
  articles/
    index.md
    <video-id>-<slug>.md
  browser-profile/
  logs/
  temp/
```

`data/` 整体进入 `.gitignore`。`temp/` 仅存放当前处理任务所需的音频、关键帧和中间结果。

## 5. 数据模型

SQLite 至少包含以下逻辑实体。

### 5.1 `videos`

- `video_id`：稳定去重键。
- `source_url`：规范化原链接。
- `title`：采集到的标题。
- `author_name`：作者显示名。
- `published_at`：可获得时保存。
- `collected_at`：首次发现时间。
- `updated_at`：最近状态更新时间。
- `status`：当前处理状态。
- `article_path`：最终文章路径。
- `content_fingerprint`：用于判断是否需要重新分析。

### 5.2 `jobs`

- `video_id`
- `stage`
- `attempt_count`
- `started_at`
- `finished_at`
- `error_code`
- `error_message`

### 5.3 `artifacts`

仅记录中间产物和最终文章的路径、类型、创建时间及清理状态。临时媒体被删除后保留清理记录，不保留媒体本身。

## 6. 状态与数据流

每条收藏使用以下主状态：

```text
discovered
  -> media_prepared
  -> extracted
  -> written
  -> completed
```

任一步骤失败时记录为 `failed`，同时保留失败阶段。重试从失败阶段继续，不重复已成功且输入未变化的步骤。

完整流程如下：

1. 用户首次运行 `setup`，完成依赖检测和本地目录初始化。
2. 用户打开独立浏览器配置并扫码登录。
3. `collector` 低频滚动收藏页，采集视频 ID、标题、作者、时间和链接。
4. `storage` 按视频 ID 去重，只将新增或明确要求重做的项目加入待处理集合。
5. `media` 为单条视频创建任务临时目录并准备音频与关键帧。
6. `extractor` 使用 `faster-whisper` 转写音频，并对关键帧执行 OCR。
7. 工具输出结构化原始材料，区分语音文本、OCR 文本和来源元数据。
8. Codex 按文章模板提炼内容并写入 Markdown。
9. `storage` 校验文章存在且内容完整，更新 SQLite 状态并刷新总目录。
10. 成功后删除该任务的临时媒体；失败时按配置保留最小诊断信息，并在下一次启动时清理过期临时文件。

## 7. 文章格式

每条视频生成一篇 Markdown，默认包含：

```markdown
# 整理后的文章标题

## 来源信息

- 原标题
- 作者
- 发布时间
- 收藏时间
- 原链接

## 内容摘要

## 整理后的正文

## 关键词

## 可行动要点

## 提取说明

- 语音转写是否成功
- OCR 是否成功
- 内容完整性提示
```

“整理后的正文”不是虚构扩写。Codex 必须以提取材料为依据，删除口头重复、修复明显断句，并在材料不完整时明确标注，不猜测缺失内容。

合集 `index.md` 按最近处理时间列出文章，并包含作者、关键词和原链接，首版不做自动主题聚类。

## 8. 媒体与模型策略

### 8.1 Whisper

- 默认使用 `faster-whisper`。
- 自动检测 NVIDIA CUDA。
- RTX 4060 Laptop 优先使用适合 8 GB 显存的模型和计算精度。
- CUDA 初始化或显存不足时自动回退到较小模型或 CPU。
- 模型选择必须可配置，并在日志中记录实际使用的设备和模型。

### 8.2 OCR

- 对均匀抽取和场景变化检测得到的关键帧运行中文 OCR。
- 对高度相似的连续 OCR 结果去重。
- OCR 失败不阻止纯口播视频生成文章，但文章中标记提取覆盖情况。

### 8.3 临时数据

- 同一时间默认只处理一条视频。
- 文章成功落盘并通过基本校验后立即删除临时媒体。
- 异常退出后，下次运行先检查并清理超过保留期的临时任务。
- 用户可运行显式清理命令删除全部临时媒体。

## 9. 错误处理

错误应使用稳定错误码，并向用户提供中文说明和可执行的修复步骤。

主要类别包括：

- `AUTH_REQUIRED`：未登录或登录失效。
- `HUMAN_VERIFICATION_REQUIRED`：出现验证码或风控，需要用户手动完成。
- `COLLECTOR_LAYOUT_CHANGED`：收藏页结构变化。
- `SOURCE_UNAVAILABLE`：视频失效、私密或不可访问。
- `MEDIA_PREPARE_FAILED`：无法准备临时媒体。
- `FFMPEG_MISSING`：FFmpeg 不可用。
- `CUDA_UNAVAILABLE`：CUDA 不可用，已回退或需要修复。
- `TRANSCRIPTION_FAILED`：语音转写失败。
- `OCR_FAILED`：OCR 失败。
- `ARTICLE_VALIDATION_FAILED`：文章缺少必要章节或未成功写入。
- `DISK_SPACE_LOW`：剩余磁盘空间不足。

验证码和风控不自动重试。普通瞬时错误使用有限次数的退避重试，达到上限后保留失败状态供用户重新执行。

## 10. Skill 与商品交付

ZIP 至少包含：

```text
douyin-favorites-article-skill/
  SKILL.md
  README.md
  CHANGELOG.md
  LICENSE
  scripts/
  templates/
  references/
  tests/
  pyproject.toml
  requirements-lock.txt
```

交付要求：

- 首版采用专有商业授权并保留全部权利；买家获得个人使用许可，不自动获得再分发或转售权。
- `SKILL.md` 能从用户自然语言触发首次安装、同步、重试和诊断流程。
- README 明确 Codex、Windows、浏览器、磁盘和硬件要求。
- 安装过程不读取用户日常浏览器配置，始终使用独立配置目录。
- ZIP 构建前执行敏感数据扫描和发布清单校验。
- 不在 ZIP 中捆绑真实 Cookie、数据库、日志、媒体、模型文件或生成文章。
- 首版通过闲鱼成交后人工发送 ZIP，更新也采用人工发送。
- GitHub 私库使用语义化版本标签，例如 `v0.1.0`。

## 11. 测试策略

### 11.1 自动测试

- 视频 ID 和 URL 规范化。
- SQLite 状态转换、去重和幂等。
- 中断后从失败阶段继续。
- Markdown 模板和必要章节校验。
- 临时目录生命周期和过期清理。
- CUDA 检测与 CPU 回退选择逻辑。
- 发布 ZIP 排除规则和敏感文件扫描。

浏览器页面解析使用保存并脱敏的最小 HTML fixture，不在测试仓库保存登录态或真实收藏数据。

### 11.2 集成测试

使用用户本人可访问的 5 至 10 条测试视频，覆盖：

- 普通口播。
- 内嵌字幕。
- 图文或大量画面文字。
- 音乐为主且语音很少。
- 视频失效或不可访问。
- 登录失效。
- 中途终止后恢复。

### 11.3 发布验收

- 新 Windows 10/11 环境可按 Skill 指引完成首次安装。
- 用户能在独立浏览器窗口扫码登录。
- 能同步新增收藏且重复运行不重复生成文章。
- RTX 4060 Laptop 能使用 CUDA 转写。
- CUDA 不可用时能给出提示并回退 CPU。
- 每条成功项目生成一篇符合模板的 Markdown。
- 合集目录能够刷新。
- 任务完成后没有残留原视频、音频或关键帧。
- `doctor` 能诊断并说明常见依赖、登录和 CUDA 问题。
- 发布 ZIP 不包含任何测试用户数据或敏感文件。

## 12. GitHub 开发阶段

### 阶段 1：仓库基础

建立 Skill 目录、Python 项目骨架、隐私优先的 `.gitignore`、测试框架、文档和版本规范。

### 阶段 2：单链接最小闭环

手工输入一条合法可访问的抖音分享链接，完成临时媒体准备、Whisper 转写、Codex 文章生成、SQLite 记录和临时文件删除。

### 阶段 3：收藏采集

加入独立浏览器配置、扫码登录、低频自动滚动、增量采集和分享链接补录。

### 阶段 4：内容增强

加入关键帧、OCR、文本去重、完整性说明和合集目录。

### 阶段 5：商品化

加入环境安装指引、`doctor`、中文故障手册、敏感数据扫描和版本 ZIP 构建。

### 阶段 6：发布与维护

在全新 Windows 环境验收，发布私有 Git 标签和 ZIP；记录抖音页面兼容性和已知问题。稳定后再单独评估是否公开仓库，以及公开时采用的开源许可证、免责声明和文档清理范围。

## 13. 成功标准

首版成功意味着：

- 一名已安装 Codex 的 Windows 用户可以按照 Skill 提示独立完成安装和扫码登录。
- 在 100 条以内的个人收藏中，工具能增量发现并逐条生成本地文章。
- 同一视频不会因重复同步而重复处理。
- 中断或单条失败不会破坏其他项目，重新运行可以继续。
- 最终长期数据中不存在原视频、音频或关键帧。
- 用户无需购买 BibiGPT 或额外转写 API。
- 商品 ZIP 不含客户隐私数据，并具备足以处理常见问题的诊断能力。
